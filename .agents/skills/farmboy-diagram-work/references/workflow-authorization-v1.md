# Bounded workflow authorization transport v1

Source/client capability1, native schema31/Feature9 unchanged. This is a consumer-owned declaration and inspection protocol, **not a host approval API or authenticated consent token**. The native store retains sole workflow/grant/ownership authority. Activating this source capability requires separately authorized matched installation, copied-client adoption and caller configuration; no current installation is changed by its availability.

## Explicit selection and bounds

`diagram-launch --authorization-file /absolute/private/source.json` selects verified transport. Unflagged invocations retain existing behavior and print `legacy_prompt_only`; they cannot claim these checks. There is no silent fallback. The source is an operator-reported, private, regular non-symlink JSON file, at most1MiB; duplicate/unknown members, invalid types or non-finite numbers are refused. Use no credentials or approval answers in it. Limits:64 distinct exact scope tuples,16 policy artifacts per checkpoint,32 conditions/exclusions and64 evidence/history references, identifiers128 characters, actor256, each prose/reference2048 and canonical repository-relative paths1024. Budgets are actual existing nonnegative signed64-bit ceilings, not grants/counters; bool is not an integer. Relative paths refuse traversal/symlinks. A current policy artifact read is bounded1MiB; native/Git reads use the existing bounded transport, with a total30second consumer inspection deadline and512KiB result ceiling.

The source's closed top-level keys are:

- `contract_version`:1; `id`: reported source ID; `project`: one actual registered Project key; `state`:active (withdrawn refuses).
- `mandate`:{actor,provenance,reference}; literal attributable existing scope, never authenticated by its digest.
- `dispatcher_effect`:dispatcher_start or dispatcher_restart, the caller's declared actual startup purpose. This field grants neither effect. A `dispatcher` scope with matching purpose/start-or-restart and explicit effect must exist for repeat startup. Stop remains a separately checked declared effect on an existing supported caller path; this feature adds no stop/kill operation.
- `conditions` and `evidence`: nonempty bounded strings referencing existing actual authority and constraints. Semantic applicability/expiry/revocation not visible in native/file evidence remains the consumer's responsibility, not a prose evaluator.
- `scopes`: the exact entries below, with no wildcard-all-project permission.

Each scope has exactly `feature,segment,purpose,candidate,effects,policy,assessment,native,budgets,history`. `feature` is an exact same-Project canonical ID. `candidate` is its protected native role commit; setup/initial captured drafting can instead use empty candidate only with the exact native captured idea hash and no historical spec approval. A dispatcher entry uses empty feature/candidate, segment dispatcher and purpose start/restart/stop. Normal segments/purposes remain setup/draft, specify/draft|flowback, clarify/clarification, plan/planning-handoff, review-plan/plan-review, deliver/delivery, integrate/integration. Selection outside the declared Project/scope stops rather than changing discovery ordering.

`effects` is a unique list drawn from: prepare_workspace,draft,clarify,plan,native_admission,local_commit,review_grant,independent_review,record_review,delivery,native_handoff,dispatcher_start,dispatcher_stop,dispatcher_restart,credential_access,external_request,integration,installation,publication. Stage selection does not invent missing effects or reset external limits. Administrative finalization requests only actual administrative admission/handoff; it does not demand or supply a fresh semantic review grant.

`policy` is {historical,current,adoption}. Each checkpoint is {commit,artifacts:[{path,sha256}]}. Historical blobs are verified independently; current blobs must match actual working bytes. Current AGENTS.md, constitution and Diagram-adapter SKILL.md must be covered when present. Adoption uses {actor,rationale,evidence,conditions}, as does `assessment`; both are explicit reported meaning, not proof that a human adopted it. Different historical/current policy is valid with actual applicable adoption; never silently copy/rewrite instructions. New unlinked preparation first checks the registered root. After an actual own active setup claim, inspect the prepared worktree before its scoped commit: it must share the registered Git instance, have explicitly covered preparation effects and match adopted policy. An existing released-setup selection may instead use the exact unheld recoverable native setup readiness, its reported stopped-writer condition, and verified preserved workspace/branch/HEAD/clean-state report; this creates or consumes no recovery right. The normal caller still verifies it is an unused nonconflicting worktree; this is not yet a native linked association. Semantic drafting refuses until native link, then inspect the actual associated workspace/pointer. Original approved-work/native identity/grant/epoch checks remain required in their maintained entries; a policy match does not replace them.

`native` has exactly {revision,handoff,spec_approval,plan_approval,idea_sha256}. Match actual current coordination. A captured initial Feature can have no native context row; its documented first-claim expected revision is0, and the observation explicitly reports native_context_present=false rather than inventing a recorded revision. Source-backed setup binds the actual queued request checkpoint, never an empty fabricated input. Own active work may advance revision while retaining original handoff/candidate/approval roles and exact owner; native epoch/operation guards still control mutation. `budgets` is {external_requests,credential_uses}; a zero ceiling refuses those selected effects. It is never decremented/renewed by transport and cannot authorize a test.

`history` references actual known effects in existing task/native evidence. Each entry is {reference,action,target,state,effect_state,new_permission,confirmed_nonexecution}; state pending/denied/uncertain/completed, effect_state none/unknown/applied. Matching prior blocked/completed effects refuse; a known denial can only reach the existing bounded retry path with actual new exact permission, positively established no execution, and its existing finite native/host rules. A new source/thread/id does not clear history. A reference/boolean does not authenticate permission or establish unseen history completeness; that responsibility stays explicit. No extra permission ledger or automatic retry is added.

## Read-only consumer invocation

The fixed adopted `scripts/prepare-authorization.py` is invoked with `--source`, `--expected-sha256`, `--selection-file`, `--workspace`, `--diagram`, `--store` and repeated `--effect`. Paths are absolute. The selection is a private JSON file with exactly {project,feature,segment,purpose,candidate,revision,owner,session,setup_required,mode}, plus optional `review_grant` only for the already selected explicit-file review route; mode is empty,revision,released-continuation,released-delivery or finalization, reflecting actual native routing. This is not authority. The launcher chooses the real registered preparation root/linked workspace; JSON supplies no command path. It explicitly runs the already adopted consumer helper, not a native core repository traversal or new installation. Before adopting code, the operator must trust that actual copied consumer; self-reported helper success cannot authenticate malicious code.

Repeat startup validates dispatcher scope/current root policy **before** guard creation, then rechecks it each cycle. Each selected child receives its exact source digest and bounded observation, which is revalidated immediately before start. The consumer checks current native Project/Feature/bindings, its actual Git policy and pointer. Missing/mismatched capability or unavailable evidence refuses before child start. No mutation is performed by preflight, including Python bytecode writes. Private transport cleanup is outside the consuming worktree.

The selected worker repeats the source/policy/native preflight before actual acquisition or scoped Git effects. An initial setup uses the registered-root preflight through preparation; after truthful link it checks the actual feature workspace before drafting. Explicitly inherited unchanged policy needs no invented per-feature exception, but unadopted/conflicting policy stops. Existing review and ordinary-handoff helpers accept paired `--authorization-file`/`--authorization-sha256` and recheck immediately before their guarded native effect. They preserve DIAG34 historical/current/output checks and unknown-terminal refusal. Other existing native/recovery/finalization leaves retain their existing action interface and require the entry's explicit pre-effect check; no new all-stage acquisition engine is introduced.

Ready observations contain only bounded source ID/digest, actual canonical workspace/selection/mode/owner/session/revision/effects, policy-artifact count, consumer_reported assurance, explicit host capabilities and limitations. Refusal returns only a bounded code and no affected effects. No raw mandate/credential/payload is logged. Mechanical snapshot checks are **not** a filesystem interlock or instant global revocation. Unknown external changes must not be claimed observed.

## Host and recovery boundaries

Current codex exec capability reports parent_approval_import=unsupported, human_response=unsupported and consumer_reported observations. It does not add a server/backend/responder. Supported ordinary tools continue through actual platform review without a new coordinator-created routine gate. A genuinely required unavailable response path stops with exact action/target/effect and preserved state.

Pending/approved/denied/unsupported/uncertain are observation states, not grant constructors. Even an observation labelled approved cannot authorize action based on caller JSON or narrative. The controlled host-response association seam matches request/session/action/target and rejects foreign/stale responses, but supplies no real host channel or automatic answer. A future real integration requires separately reviewed adoption and genuine user interaction.

Existing actual host denials, security settings, normal hooks, native holds/revocations/grants/ownership, consumed continuation/finalization and external budgets remain controlling. Inspect uncertain effects before any permitted retry; new labels cannot renew rights. No app-server acceptance, permission token, security/profile change, live-model/API proof, automatic policy rewrite, migration, integration or publication follows.

## Explicit review grants and refusal diagnostics

Verified review retains both existing grant routes. Before admission, the existing launcher validates its actual `--review-grant-file` and transports that normalized grant in the private selection only when no native publication applies. The consumer checks its exact feature/handoff/revision/reviewer/session and bounded review-only shape. It never creates a native publication to make this route work. After admission, the actual own native run's immutable original grant supplies that binding; a caller cannot substitute another grant. A matching consumed publication must still name this run, and a matching withdrawn/foreign-consumed grant refuses. Existing native grant revocation and reviewer-independence checks still run atomically at admission/terminal; consumer inspection does not claim to observe every historical revocation. Administrative finalization remains distinct. (DIAG-35 R1)

A consumer refusal has exactly `{contract_version:1,status:"refused",reason:CODE,effects:"none"}` and exits1. The launcher propagates only this duplicate-free, unknown-field-free envelope, at most1KiB, with a known version1 code and its actual selected project/feature/stage. No raw source, stderr, prose, secret or purported grant is echoed. Process/timeout/malformed/unknown-code failures keep the generic unavailable diagnostic. `policy_stale` requires inspection of the declared current workspace/policy before affected effects; `scope_missing` identifies absent effect scope rather than another routine feature approval; native/grant binding codes require current authority inspection. A diagnostic is an observation, never a new permission or replay right. (DIAG-35 R2)

Selected native grants are separate existing authority records, not carrier prose. Their normalized native shape, nonblank required authorization strings and nonempty/nonblank conditions are preserved under the existing bounded selection/native-response transports. The carrier's own2048-character/32-condition limits do not narrow an otherwise valid native grant. Existing caller/native guards still assess actual authority, exact input and independence; accepting the transport is not consent.
