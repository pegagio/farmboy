# Dynamic review authority v1

DIAG-25 source capability requires matched schema27/Feature9 Diagram and launcher. It is not installed by source availability; explicit preserving26→27 upgrade, deployment and activation require separate authorization. Existing live schema26 coordination can continue on its installed tools while this candidate is reviewed. This capability changes transport and availability of an existing exact caller-issued grant; it creates no approval role or stage-execution permission.

## Native publication and current truth

`diagram feature review-authority show --feature ID --json --file STORE` inspects the existing Feature9 snapshot plus current `review_authority_applicable`/`review_authority_reason`. Its context may contain a version1 `review_authority` envelope: publication_operation, unchanged grant, canonical grant_sha256, state published/consumed/withdrawn and consumed_run_id when admitted (retained on later withdrawal). Reads acquire nothing.

`diagram feature review-authority publish|withdraw --feature ID --operation OP --request-file FILE --json --file STORE` accept one strict review-authority1 JSON object, at most1MiB. Responses and immutable existing operation receipts remain Feature9 snapshots; publication is not a new decision or owner. Unknown fields, trailing objects, incompatible versions and conflicting operation payloads refuse.

Publish supplies expected_revision N, expected_queue_revision, exact dependencies, pinned_handoff, previous_publication (empty only for absent slot), review_grant and attributable assessment. Assessment must carry actual applicable spec-approval/condition verification. Caller must have actual human bounded approve/return delegation, preserve protected intent/constraints and select an independent reviewer owner/session. The grant's existing expected_revision is explicitly N+1, and its Feature/handoff/reviewer and authorization are validated against the projected post-publication context. Native never repins/rewrites its bytes. Complete released pending plan, correct current spec approval, queue/dependencies/identity and absent writer are required. Publication may occur with review OFF; availability does not enable or launch it.

Replacement explicitly names the old publication and supplies applicable new mandate for the exact projected revision; only with no active reviewer. One transaction revokes prior published digest using existing approval history and replaces the slot. Withdrawal supplies current expected revision, pinned handoff, exact prior publication/digest, attributable revoke-plan-review Review (actor/provenance/outcome/approach/nonempty conditions) and assessment, with no new grant or unrelated authority fields. It records exact revocation plus withdrawn state together. With an admitted review it targets only that captured grant, retains owner/process and lets existing terminal fencing reject revoked judgment; no kill/release is implied. Turning a workflow OFF is distinct from withdrawal.

Every availability mutation advances coordination revision once. Competing same-N changes serialize; stale selection/admission refuses. Native admission atomically consumes the exact published slot with exclusive reviewer run creation, retaining publication identity and original grant/digest in original input/history. Interrupted released review cannot be renewed by publication, withdrawal/republication, new operation labels or restart. A genuinely new plan handoff requires fresh applicable delegation. Active-owner resume/replace remains governed by its prior semantics.

Operation replay returns the original receipt without restoring a slot/run/decision. An uncertain response requires inspection of the same operation and current Feature before any permitted retry. Corrupt/digest-mismatched/unreadable/ambiguous stored authority stops visibly; it is not an absent grant.

## Same-process discovery and legacy transport

Default `feature eligible` uses published authority. Known missing/stale/revoked/used grants exclude only that pending review, leaving normally eligible other work in existing order. Project/workflow toggles, queue/dependencies, stage/identity and exclusive ownership remain necessary. Fresh launcher selection re-reads native authority, compares publication/digest/revision and transports unchanged grant/reviewer labels to the existing Farmboy independent reviewer. Native admission revalidates after spawn: a stale race can produce a refusing child, never a silently rebound grant.

The same guarded foreground checker handles review and other separately authorized workflows without restart or grant-file swapping. It still awaits one child. Review OFF blocks new launch, not an active child or the grant itself; reenable permits only still-applicable authority. Observer requires committed report/exact input/native approve-or-return/released ownership, not exit zero alone. Failed admission/child/observation follows normal stop-and-inspect; no hidden retry.

`--review-grant-file` remains explicit invocation-scoped review-only mode, rereading its regular JSON file at selection. Its launcher requests `feature eligible --review-authority-mode explicit-file` to preserve the prior technical review offer without requiring native publication. This read selector grants no admission authority; supplied file must still pass exact grant checks. Default mode is `published`; unknown modes refuse. An applicable native publication plus supplied file is ambiguous and refuses; a known stale/used/withdrawn slot alone is not conflicting authority. File authority never leaks to non-review stages or becomes standing native policy.

## Compatibility and deliberate exclusions

Explicit26→27 adds only nullable review authority storage; migrated legacy features have no publication. Preserve existing rows/context revisions, historical JSON/digests/receipts/revocations/decisions, continuation holds/consumed allowances/legacy opt-outs and controls. Upgrade refuses active owners and malformed/unsupported stores, rolls back failures and validates integrity. Old receipt replay retains historical meaning; operational access never auto-upgrades. No new tables/services/authority ledger.

Human whole-spec approval, separate implementation selection, result acceptance and integration permission remain. No automatic grant creation/rebinding/renewal, released-review/integration continuation, host restart/lock cleanup, API/credential rights, permission bypass or budget reset. DIAG-24 continuation and DIAG-26 harness recovery are distinct. Controlled fixtures prove process/native/Git plumbing and scripted verdicts, not actual model obedience or authentication of human consent; real dogfooding needs separate authority.
