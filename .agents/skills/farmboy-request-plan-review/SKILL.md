# Arrange one independent plan review

Handle one selected independent whole-plan review as the selecting caller. Use the current model/effort and existing host session tools; this is a thin composition, no new API, no registry, no supervisor or standing mandate. The caller may have authored the proposal but never makes its independent decision. The separate reviewer must have no material authorship.

## Resolve the selected request and authority before effects

Read actual project instructions, governance and the request. Resolve exactly one Feature/current saved complete proposal, approved specification and applicable actual bounded human mandate. An ordinary request to arrange review in the selecting/authoring session enters here; an already dispatched independent reviewer enters the existing `farmboy-review-implementation-plan` body and must not call this selecting entry recursively.

Review alone is not delegation. Reuse settled explicit candidate-specific human authority, including protected intent/UX/constraints and permitted role. If Feature, exact candidate, reviewer independence or substantive approval scope is missing/ambiguous, ask one concise question for the missing decision, then wait without dispatch. Never ask the operator to copy a prompt, construct JSON or repeat already settled authority. For advice-only authority or reserved human plan acceptance, do not submit a delegated-plan-approval grant or invent a native advisory lifecycle; state the missing applicable route/role and ask only whether the operator wants to supply it. Access, automation flags, labels, checklist success and silence are not a mandate.

Inspect actual Git/spec/plan/tasks/checklist/design/fresh analysis and current author handoff/release. Verify immutable proposal/artifact identities and native/current applicability before dependent work. A stale/changed candidate, active author, conflicting ownership, hold/revocation, unknown association or unavailable required evidence stops with the exact issue. Never repin/renew a grant or release another writer to make review start.

Standalone routing has no Diagram dependency: retain actual explicit project/governance bounds and provide equivalent verified candidate/mandate context to the existing independent reviewer. Deliberately Diagram-enabled routing uses the existing optional adapter and its adjacent native protocol; missing capability never falls back to standalone. Preserve installed clients/store/config, controls and normal human approval gates.

## Prepare one complete caller handoff

Verify an exposed, supported way to start an independent session and inspect/wait for its result at this exact selected project/workspace. Prefer the host's existing independent subagent/session tools; creating another user-facing task requires its ordinary explicit authorization. Use actual available tools, not invented aliases, assumed profiles or an install request. Inability to target or inspect the independent reviewer is a precise capability stop before dispatch, no new selector or discovery/filter/controls override.

For Diagram, inspect current Project/Feature/queue, review-ready handoff/revision, accepted-spec/proposal references, actual applicable spec decision and absence of conflicting current writer. Choose independent native reviewer owner/session labels for the new separate session and retain their actual correspondence to its host identity; labels are attribution, not authentication. Assemble the existing native ReviewGrant from actual human evidence, using only its existing fields:

- `feature`, `pinned_handoff`, `expected_revision` identify this exact current Feature/candidate.
- `reviewer_owner`, `reviewer_session` identify the selected independent reviewer.
- `authorization` is the existing human Review: actual actor/provenance, `decision: delegate-plan-review`, bounded outcome/approach and explicit nonblank conditions preserving intent/UX/constraints and stop boundaries.

Use an ordinary existing JSON serializer when transport needs a file. The reviewer receives caller-supplied authority: no self-issued grant and no instruction to invent one. Never infer a missing human decision, substitute identities or silently broaden scope. The object's shape is the existing native contract, not a new handoff packet or service.

Send a complete initial prompt/context to the actual separate reviewer: selected Feature and segment, immutable spec/proposal/checklist/design/analysis/architecture references, actual human authorization/bounds and independence evidence, applicable project instructions, exact supplied grant/native labels and existing store/config, full report/native-release endpoint, scoped report/checkpoint permission and restrictions. Do not prescribe the substantive verdict. Permission to arrange review covers this single independent reviewer invocation, not implementation or arbitrary additional workflows.

Use the existing explicit manual independent-session entry to `farmboy-review-implementation-plan`/`farmboy-diagram-work` when that route is supported. The adapter alone acquires/reuses native review authority, invokes its single semantic body, checkpoints the report with normal hooks, finalizes and verifies release. Caller must not acquire/finalize on its behalf or write the proposal. Inside that reviewer session use one continuous invocation, no per-step agents.

An existing launcher route may instead pass `--review-grant-file` only when actual native discovery selects this exact review-ready candidate; supplied grant is supplied unchanged. That flag does not target arbitrary manual work. Missing/mismatched grant, controls or scope stops under existing rules; never enable controls, skip candidates, add a flag or use another route to bypass a refusal. Existing `--add-dir` and all ordinary permissions remain invocation-specific, not permission expansion by review selection.

## Dispatch once and collect the actual outcome

Start at most one reviewer for this selected request through the verified tool. Retain the actual returned child identity and existing operation/Feature/candidate locators in ordinary session evidence; there is no separate status file/dispatch ledger. An already dispatched matching reviewer is inspected/collected: do not dispatch again. Do not provide the plan author as reviewer or turn a reviewer into a selecting caller.

Use the existing read/wait tools and inspect actual reviewer progress/result. Normal quiet work is not failure; a concrete stall or missing capability is inspected within authority without creating a duplicate session. A failed/uncertain start, disconnect or unavailable child remains unknown. On resume inspect the known session and native operation/current authority and saved evidence before any further effect; historical replay grants no current ownership and never repeats completed review. Missing needed locators is a precise manual-inspection stop, not proof nothing happened.

Read and verify the actual returned fields: `report_reference` path and SHA-256, `reviewed_candidate`, `reviewer_mandate`, `findings`, `disposition`, or `incomplete`. Compare actual saved/committed report bytes and original candidate/mandate. For completed native review, inspect accepted native terminal, separate report checkpoint and absent owner/claim, with exact expected reviewer/epoch/input correlation through existing adapter/native records. A report file, process exit, prose or old receipt alone is insufficient. Native acceptance checks metadata consistency, not physical Git truth or human prose authentication.

If permissions/commit/hooks/native finalization fail, or returned evidence is invalid, stale or uncertain, retain known work and report incomplete: exact action, target, reason, completed effects and denied/pending/uncertain outcome plus next inspection/input. Do not invent approval/release, clear someone else's ownership, retry blind, switch checkout/executor after refusal, expand permissions or ask another agent to bypass it. The reviewer adapter handles only its own supported release when appropriate; caller never becomes recovery authority.

## Return and stop

Return the Feature and original reviewed candidate, actual reviewer/human mandate, report path/digest/checkpoint, concise answers to the six prescribed questions, required versus optional findings, actual native disposition/handoff/release or truthful incomplete, and the next separately authorized action or genuine human decision. Attribute delegated approval to the reviewer and actual human mandate; do not claim the human personally reviewed the proposal.

Preserve existing approve, planning-return and specification-escalation meanings and FARM-27/FARM-28 downstream evidence semantics. No automatic repair, re-review or next child follows. Plan approval is not implementation permission; actual specification change still requires human whole-spec approval, and result acceptance/integration/publication remain separate. End this selected caller invocation at the collected result or precise input/blocker. Consumer refresh, installation, scheduler activation, merge/push or a universal “drive feature” workflow is never an effect of this skill.
