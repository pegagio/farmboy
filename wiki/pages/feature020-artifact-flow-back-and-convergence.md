# Feature 020 artifact flow-back and convergence

## Feature 020 retained scope and task repair

Implement retains trusted requested task scope independently of the currently executable subset. A full-feature request includes existing unfinished tasks; an explicit subset remains restricted. After prerequisite completion, fresh readiness, eligibility, exact assignment and owner-route validation can activate newly eligible scoped work in the same invocation. Exhausting the initial subset alone is no completion or stop. Scope, authority, independent review, safety and iteration guards remain intact. (S029)

Independently evidenced in-scope defects route bounded task revision to exact FlowKit-Tasker, preserving IDs, findings, unrelated markers, completed work and accepted decisions. The controller validates the actual revision and frozen scope before coding; fresh independent code assessment follows. Only independently evidenced completion of previously unfinished substantive scoped implementation work or resolution of a previously recorded defect earns implementation progress. Administrative prerequisite fulfillment can discharge requested accounting but earns zero source-progress credit. Task edits, marker changes, reports and newly discovered findings earn none. (S029, S031)

**Accepted chronological supersession**: S021’s earlier wrapper excludes task revision. Feature 020 adds bounded exact-Tasker repair within retained authorized scope; the current protocol confirms Tasker-owned marker updates and finding-linked revisions after independent review, with fresh scope/readiness/history validation before coding. Earlier constraints remain historical; the replacement permits no material expansion, budget reset or implicit later workflow. (S021, S029, S030)

## Scoped fulfillment and completion proof

Administrative prerequisite fulfillment needs exact task requirements, actual trusted operator decisions where required, permitted effects with observed before/after state or no-op, independent reviewer execution attribution and proof that source correction did not occur. It can discharge dependency/subset accounting for exact Tasker tracking, but supplies no implementation resolution ID or independently completed implementation task. Any task requiring source correction remains substantive; administrative reclassification cannot evade coding and independent review. (S031)

Substantive completion requires the whole task's requirements, frozen activation/source preimages, attributable effects, relevant validation and actual independent Code Reviewer proof. A resolved prior defect may justify continuation while its parent task stays open; whole-task completion still needs complete independent substantiation with no unresolved owned finding. Exact FlowKit-Tasker owns marker tracking and bounded revisions after validated evidence; neither author claims nor marker changes supply completion proof. (S031)

Boundary records retain original requested identities/provenance, current eligible and pending IDs, actual completed effects, independently completed implementation IDs, administrative prerequisites, outside IDs, unresolved findings, decisions and iteration/stop routes. Administrative-only completion reports **Scoped prerequisites fulfilled**, zero implementation progress and explicit outside/pending feature work, without an implemented milestone. A substantive subset reports its exact boundary. Full-feature implementation requires independently fulfilled complete substantive scope and no associated buildable defect; scoped completion implies no convergence, verification or acceptance. [Lifecycle outcomes](./feature020-workflow-lifecycle.md) likewise preserve partial effects and recording uncertainty. (S031)
