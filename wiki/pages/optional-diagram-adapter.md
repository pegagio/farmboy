# Optional Diagram adapter

Farmboy's optional `farmboy-diagram-work` skill composes the existing Diagram CLI, three Farmboy external entries and ordinary clarification for one selected segment. The consuming agent verifies repository/Git/workspace/artifacts; Diagram records authority, approvals, transitions and report consistency. Documentation and source availability alone establish no runtime acceptance. (S012)

## Deliberate routing and compatibility

Project instructions or explicit operator selection establish the route. Availability alone never enables Diagram. Standalone entries retain local behavior without an adapter dependency; missing/conflicting routing asks targeted input, and an unavailable enabled capability stops without installation, fallback or external software patch. Enabled use requires an actual compatible executable/store: Feature6/schema16, independent Project/Repository2 and affectedIssue3. No store migration/reset or installer is added. (S012)

All three Farmboy-owned entries have small route/return seams. A first enabled entry invokes the adapter once; a verified current inner invocation reuses native authority without recursion, duplicate effects or premature release/Goal completion. Stale/foreign context and Boolean flags alone grant no authority. Native protocol stays in the optional skill/reference; no registry, plugin API, service or new store is introduced. (S012)

## Handoffs and limits

Initial claim permits setup only; external workspace verification precedes link, which admits full initial draft authority without an extra acquire. Saved human handoffs require actual recording/release readback; separately selected clarification holds authority between genuine questions. Whole-spec approval gates planning, whole-plan approval gates delivery, and committed delivery ends at result review. Result acceptance supplies no integration or push permission. (S012)

Segment launch discloses necessary scoped checkpoint commits with normal hooks and user restrictions. Preserve unrelated staged/unstaged/untracked work; unsafe isolation saves precise input, while failed hooks remain technical blockers. Only explicitly selected matching whole-adapter Goals can complete after saved/read endpoints and release; no automatic Goal restart, custom recovery framework or receipt-only tail commit is added. Consumer physical verification remains necessary because accepted consistent reports do not prove filesystem truth. (S012)

The [integration direction](./diagram-integration.md) preserves the historical goals and separate integration boundary; [workflow handoffs](./workflow-handoffs.md) describe generic standalone/external execution. This component adds optional coordination to those existing contracts without making their earlier source documents runtime evidence. (S012)
