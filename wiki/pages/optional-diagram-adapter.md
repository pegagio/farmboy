# Optional Diagram adapter

Farmboy's optional `farmboy-diagram-work` composes existing CLI, external entries and ordinary clarification for one segment. Consumer verifies physical facts; Diagram records coordination authority/report consistency. Source alone proves no runtime acceptance. (S012)

## Deliberate routing and compatibility

Project instructions or explicit operator selection establish the route. Availability alone never enables Diagram. Standalone entries retain local behavior without an adapter dependency; missing/conflicting routing asks targeted input, and an unavailable enabled capability stops without installation, fallback or external software patch. The original005 source baseline was Feature6/schema16; subsequent historical guidance described Feature8/schema19 and review Feature9/schema20. Those are historical compatibility targets, not current operational instructions. Current segments use the active project-selected matched client; the present native reference identifies Feature9/schema22. Do not use a newer client on an older selected store or infer migration/install authority. (S012, S014)

All three Farmboy-owned entries have small route/return seams. A first enabled entry invokes the adapter once; a verified current inner invocation reuses native authority without recursion, duplicate effects or premature release/Goal completion. Stale/foreign context and Boolean flags alone grant no authority. Native protocol stays in the optional skill/reference; no registry, plugin API, service or new store is introduced. (S012)

## Handoffs and limits

Initial claim permits setup only; external workspace verification precedes link, which admits full initial draft authority without an extra acquire. Saved human handoffs require actual recording/release readback; separately selected clarification holds authority between genuine questions. Whole-spec approval gates planning, whole-plan approval gates delivery, and committed delivery ends at result review. Result acceptance supplies no integration or push permission. (S012)

Segment launch discloses necessary scoped checkpoint commits with normal hooks and user restrictions. Preserve unrelated staged/unstaged/untracked work; unsafe isolation saves precise input, while failed hooks remain technical blockers. Only explicitly selected matching whole-adapter Goals can complete after saved/read endpoints and release; no automatic Goal restart, custom recovery framework or receipt-only tail commit is added. Consumer physical verification remains necessary because accepted consistent reports do not prove filesystem truth. (S012)

The [integration direction](./diagram-integration.md) preserves the historical goals and separate integration boundary; [workflow handoffs](./workflow-handoffs.md) describe generic standalone/external execution. This component adds optional coordination to those existing contracts without making their earlier source documents runtime evidence. (S012)

The [independent reviewer](./independent-plan-review.md) adds a generic semantic body with ordinary report/return content; its adapter alone owns the native review lifecycle. Adoption is explicit and does not follow from source availability. (S013)

## Conditional planning admission

When a verified applicable approval carries review conditions, assessment.conditions supplies truthful present applicability to the exact approved artifacts and requested phase. It is not copied restrictions, a placeholder or inferred permission; without conditions, do not invent a synthetic entry. Request and assessment approval references identify the same actual historical specification decision. (S014)

Before the first acquire, use a typed read-only planning offer with its required request file and verified repository/HEAD/cleanliness reports. An offer grants no run. A definitive launcher acquire rejection still stops that invocation without resubmission; inspect uncertainty before effects. The TEST ONLY worked example explains these existing native requirements without changing validation, launcher behavior or authority. (S014)
