# Standalone and externally selected workflow handoffs

All three existing Farmboy skills expose standalone and explicitly externally selected entries. The human-readable contract does not add a bridge command, transport, fixed packet or runtime loader dependency. This records prescribed behavior, not runtime acceptance of a particular candidate. (S011)

## Entry and context

Standalone retains local roadmap/wiki conventions. Externally selected execution receives one feature, request/intent, segment and accessible references; existing Git constitution/direction/feature artifacts govern rules/context. Farmboy checks those documents without repeating queue eligibility/activation or recreating retired queues. Identify revisions/current working state as needed and ask for specific material stale/conflicting/missing input before dependent work; no invented answers, fixed provenance packet or reapproval of unchanged work. (S011)

Core helpers use the caller-established contained workspace association. Explicit identity, pointer and effective environment directory must agree before normal helpers, which can persist the environment value. Helper-dependent entry requires the existing pointer and a would-be persisted literal equal to its value; resolved aliases alone can still rewrite it. Missing/no-write-mismatched association is specific caller preparation input, never silent environment/pointer normalization, retargeting or temporary replacement. (S011)

## Outcomes and authority

Draft preparation returns Needs clarification or Awaiting spec review before ordinary clarification. Planning requires applicable specification approval and returns full-plan review after actual plan/tasks/read-only analysis and separate repair. Delivery requires applicable spec/full-plan approval and returns a scoped committed local candidate for result review; external execution makes no local or Diagram queue-status write. Configured relevant wiki maintenance remains applicable without requiring an absent wiki. (S011)

Outcomes identify work, artifacts/evidence, remaining input/blockers and next review/action. Keep actual committed references distinct from base revision/current dirty artifacts, and historical reviewed checkpoints distinct from accepted handoffs. Resume preserves answers/performed work and pending review, reassessing affected work only. No native completion, result or check approves work or authorizes another segment. (S011)

Diagram retains selection/ownership/approval/accepted-handoff authority. One active owner permits sequential handoffs; draft return enables coordinator release, while ordinary clarification separately acquires authority retained while active. Farmboy implements no ownership acquisition/release/transfer service. Standalone needs no Diagram service. (S011)

[Integration direction](./diagram-integration.md) describes the separate final-result/UAT authorization, policy and receipt boundaries. Human authorization and project branch/target/check policy govern later integration; Diagram serializes and owns database-only receipts referencing Git. No implicit push, recursive project receipt commit, executor implementation/placement, scheduler or autonomous worker is included. (S011)
