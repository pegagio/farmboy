# Existing artifacts and context —025

No database or new persisted model is added. These names describe ordinary artifact content.

- **Candidate:** one feature identity; approved-spec reference; exact proposal artifact references (commit/path/SHA-256 when committed; base plus paths/digests/current uncommitted state otherwise); checklist/design/analysis and relevant architecture. Required correlation; unavailable or changed material evidence stops review.
- **Mandate:** actual reviewer, human authorization provenance, bounded role/intent/UX/constraints and required independence evidence. Nonblank and applicable; no material proposal authorship. A label is attribution, not authentication.
- **Report:** contained feature-relative validation/plan-review.md, actual SHA-256, exact candidate/mandate/reviewer, six answers/rationale, findings and disposition. Review does not edit proposal bytes. Optional findings are non-blocking and cannot conceal an unmet obligation.
- **Return:** report reference, candidate correlation, reviewer/mandate reference, findings, disposition or incomplete/error detail; constraints in contracts/review-return.md. Same-session content, not a persistent transport schema.
- **Native context (adapter only):** existing Feature9 grant, owner/session/run/epoch/dependency/input pins. Adapter acquires/reuses once; reports accepted native disposition or preserved incomplete state, then release/readback. Never copy this as generic state.

Substantive native transitions remain approve→plan_approved, planning return→plan_revision_required, specification escalation→specification_change_required. Incomplete is no substantive decision. Human specification approval remains historical and no transition launches later work.
