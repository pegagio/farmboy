# Existing artifacts and revised stage boundaries

Conceptual relationships only; no new persisted schema.

| Concept | Existing representation | Meaning |
|---|---|---|
| Selected feature | Roadmap, active pointer, feature directory | Revalidate identity before effects; no duplicate activation. |
| Draft | Spec, quality checklist, roadmap brief | May contain explicit material questions without inventing answers. |
| Successful automated handoff | Existing spec metadata/note and readable summary | Saved usable draft plus next stage: ordinary clarification or human review. |
| Native preparation Goal | Existing host-owned Goal state | Complete at draft/handoff; never kept active to await answers. |
| Interactive input | Core clarify and existing Clarifications section/conversation | Genuine answer wait outside the completed Goal; answers flow back. |
| Human approval | Explicit operator decision and existing artifact reference | Separate from Goal/clarification completion; prerequisite for planning. |

Automated drafting → completed handoff → ordinary interactive clarification when needed → human spec review/approval. Interrupted drafting may resume; a completed handoff is not another draft activation. A blocker/stall is not success. These are workflow concepts, not new canonical lifecycle values or authority stores.
