# Prepare specification validation procedure

This procedure is not evidence by itself. Actual completed observations and their limitations are recorded in [acceptance evidence](validation/acceptance.md). Use the actual revised skill in a separate real subject in a disposable project; preserve current model/effort and existing tools.

1. Prepare an ambiguous bounded feature. Run automated preparation with a native Goal whose entire objective is a saved usable draft and explicit handoff. Record native completion before any question answer; a stalled/paused state is a failure of this objective. Check saved ambiguities, findings, next-stage links and absence of further automatic turns.
2. Prepare a settled feature. Observe native completion at human-review handoff, with no invented questions.
3. Outside the completed Goal, explicitly invoke existing `$speckit-clarify` ordinarily. Observe one actual question and genuine wait, then supply a test-only answer. Inspect reconciliation, supported additional rounds if needed, and the separate review handoff. The completed preparation Goal stays completed.
4. Without explicit spec approval, request the next phase in the fixture and confirm planning does not start. Clarification completion and test answers are not approval. Observe recognition of an explicit test-only approval separately, without running a later workflow.
5. Check interrupted drafting versus completed-handoff resume, identity/context negative cases, changed artifacts and no duplicate effects proportionately. Keep artifacts and recorded native states as evidence; no roleplayed subject or fixture-only success.

Record actual versions/source hashes and observations in `validation/acceptance.md`. Preserve historical failures. Stop for unavailable capabilities and review actual outcomes; no database, permission, controller or upstream-policy workaround is authorized.
