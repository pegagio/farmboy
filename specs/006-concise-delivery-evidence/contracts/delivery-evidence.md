# Delivery evidence behavior contract

The interface remains the existing Farmboy delivery invocation and saved/returned handoff. No new command, parameter packet, API or store is added.

**Inputs:** Selected feature, approved current spec/full plan, applicable project evidence rules, current Git/worktree state and actual performed results. Existing standalone/external routing and authority checks still apply.

**Before the final scoped commit:** Identify durable deliverables/reusable assets versus disposable run material; preserve a concise source/check/result/repair/limit/decision account. Validate required references against retained artifacts. Inspect actual staged scope, including tracked raw files, without disturbing unrelated work. Use portable paths and role attribution rather than private names/session identifiers. A raw durable exception needs a concrete essential need or project rule, minimal safe content and an explicit reason.

**On conflicts or missing proof:** Save the precise limitation and remaining action; stop dependent closeout. Do not turn missing logs into a pass, fabricate approval, weaken required verification or change installed core command contracts.

**On consolidation:** Only authorized mutable reports may be replaced. Preserve distinct material claims/decisions and repair required links. Preserve historical merged meaning and required command-generated artifacts. This implementation initially demonstrates consolidation in the disposable fixture rather than sweeping old Farmboy features.

**On return:** Actual committed candidate and required evidence references remain reviewable after disposable output disappears. Temporary diagnostic pointers are optional/labeled disposable. Report actual resulting commit without receipt-only recursion. End Awaiting result review; execution, checks and summarization cannot grant acceptance, integration or push. Externally selected execution returns existing caller data without queue/ownership/approval writes.
