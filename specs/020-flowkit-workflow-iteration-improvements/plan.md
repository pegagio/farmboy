Semantic intent and review judgment stay with the assigned controller/reviewer; code validates identities, ambiguity, evidence freshness and state before mutation. No dependency, framework, service, existing-role setting or capacity mechanism is introduced. The operator-approved additive `FlowKit-Readiness Checker` has a native `gpt-6-luna`/`medium` definition. This 2026-10-06 amendment replaces the original core-evaluator delivery proposal; it is prospective design, not implemented readiness evidence.

## Design and Ownership

Three contracts define boundary behavior; a fourth defines evidence accountability. [research.md](research.md) records source observations and rejected alternatives.

### Trusted intent and feature activation

Main-task semantic classification distinguishes explicit activation/amendment from interest, discussion and evidence. It supplies a bounded operation/target/scope record tied to a direct user instruction. That record is inspectable context, not an authentication credential: a JSON flag, child claim or feedback file cannot manufacture authority. A deterministic `selection.py` helper normalizes stable numbers, `F`/`Feature` prefixes, exact titles and explicit menu references against a current validated inventory; it returns selected, ambiguous or missing, never silently prefers an ordinal over a competing stable ID.

Select Feature still performs complete inventory/dependency checks and uses fresh Roadmap Agent preparation. Its reviewed graph conditionally requests a choice only when target authority is unsettled, and requests patch approval only for an unrequested/inferred consequential change under the prospectively approved governing rule. An eligible target with empty patch goes straight to validated pointer activation; it does not call Roadmap Write for a no-op. A missing/stale mapping requires a visible supported proposal and current authority check, never an automatic target substitution. Independent Reviewer verifies exact mapping, preserved existing spec bytes, resulting pointer and permitted lifecycle state.

Immediately before effect, re-read roadmap/dependency/pointer state and compare the prepared fingerprint; changed state requires fresh validation, not an obsolete prepared payload. Reuse `activate_feature` atomic replacement, preservation of additional JSON fields and no-op behavior. Planned/no-spec activation retains planned without creating a directory. Existing consistent lifecycle/spec state is preserved; a planned authored spec is not automatically a contradiction because the separately authorized roadmap transition may remain pending. Undefined state, terminal-state reactivation and genuine contradictory evidence stop with focused resolution.

### Honest preparation and independent ownership

Implement a FlowKit-owned deterministic readiness helper in the existing controller Python package. It verifies the active feature, safe paths, complete checklist coverage, marker counts, item locators, input/evidence digests and freshness. `FlowKit-Readiness Checker` is a dedicated read-only native agent configured as `gpt-6-luna` with `medium` effort. It interprets the bounded helper report against established classifications and existing verdicts, returns stable readiness gaps, and cannot create review approval or edit the checked artifacts. Existing Reviewer model/effort and substantive independent-review responsibilities remain unchanged.

Preparation checklists contain preparation-quality/review obligations only. Future implementation and acceptance obligations remain pending outside `checklists/`, preferably in an existing feature validation artifact. A mixed/legacy checklist requires explicit current owner classification, source/destination preservation and an authorized recording step; ambiguous obligation purpose blocks. Do not mark future outcomes complete, silently drop them, rename a required preparation review as future evidence, override the core gate or edit core templates/installed helpers. Optional feature-local `preparation.json` covers nonstandard obligations and relocation provenance without duplicating every ordinary checklist.

### Readiness findings and authorized correction

Analyze and Remediate retains its initial read-only baseline and existing six assessments/five-correction limit. Run fresh core artifact analysis and the read-only Checker on current inputs; retain both reports as separate authoritative finding sources. The existing FlowKit-Reviewer assesses artifact findings, while the controller merges them with readiness gaps without substituting the lightweight Checker for substantive review. A combined clean state requires both reports clean and the unchanged core checklist scan to have zero unchecked preparation items. Artifact analysis success alone is insufficient.

Every readiness gap has a stable ID, exact source/item, missing evidence, declared owner, proposed correction, authority status and due phase. Route safely repairable in-scope findings to the smallest declared owner correction: built-in quality to Specifier, plan defects to Planner, task defects to Tasker, missing independent judgment to Reviewer, and supported verdict/marker recording or future-obligation relocation to a main-task recorder. Plan/spec corrections retain required downstream reconciliation. Read-only assessors never edit markers. The recorder revalidates source/destination and verdict digests immediately before effect and persists only authorized evidence-backed changes. Unsupported ownership, new product/governance/scope decisions and ambiguous recovery block before mutation. Do not invoke another FlowKit workflow.

After any correction, rerun current artifact analysis and a fresh Checker assessment; retain unresolved and new findings under stable identities. Credit progress only for independently substantiated resolution of a prior gap, such as a genuinely corrected defect or a newly supplied required verdict; report writes, timestamp refreshes, checkbox flips or obligation relocation without semantic resolution earn zero progress. Honor the existing cap and no-progress stop. If the Checker or correction owner is unavailable, stop with exact assignment/step and safe resumption rather than a fallback or an invented approval.

FlowKit Implement repeats the same helper/Checker policy against current feature inputs immediately before core `speckit.implement`; a saved Analyze result is evidence, not permission. Block stale inputs or any unchecked/unresolved preparation obligation before Coder dispatch. For ready preparation, core sees its ordinary all-checked gate and proceeds without a future-evidence override. Future evidence remains pending elsewhere. A startup finding is reported with a safe Analyze resumption action; Implement never automatically invokes Analyze or expands its declared correction scope.
