# Selecting caller and independent review handoff contract

This is an instruction/return boundary, not a new JSON API or orchestration service.

## Caller entry

Input is the actual operator request plus accessible authoritative project/Feature/current proposal and human scope. Resolve the existing route and exact candidate. The operator does not construct grants or copy prompts. Missing Feature/role/protected scope asks one concise question; existing explicit authority is not asked again. Review/advice alone does not authorize native delegated plan approval. Standalone use preserves its explicit governance and carries equivalent bounds without native dependencies.

Before dispatch establish: actual candidate bytes; approved specification applicability; current author handoff/release and no conflicting run; reviewer independence and distinct owner/session labels; available exact-target independent-session and result inspection route; normal permissions. A stale, held, revoked, missing or unverifiable fact stops without a substitute feature, new selector or changed controls.

## Existing Diagram grant and reviewer context

Use the current native `ReviewGrant` from `modules/diagram-cli/internal/feature/plan_review.go` at the pinned compatibility source. Existing fields are `feature`, `pinned_handoff`, `expected_revision`, `reviewer_owner`, `reviewer_session`, `authorization`. Existing authorization Review contains actual actor/provenance, `decision: delegate-plan-review`, bounded outcome/approach and explicit conditions. This document adds no fields or validation layer. Ordinary transport JSON may be serialized with existing tools; never fabricate a reviewed candidate or human decision.

The selecting caller chooses the independent reviewer identity before dispatch and supplies the complete existing object plus truthful human evidence, immutable proposal/spec/report paths, selected store/config and whole endpoint in the initial task/prompt. The reviewer receives caller authority; it does not generate a missing grant. A host thread ID and native reviewer labels are different observations; record actual correspondence rather than equating them. Requesting a different reviewer or changed candidate requires actual applicable scope, not silent label/grant substitution.

If using the existing run-once launcher, `--review-grant-file` transports that object unchanged only when native discovery actually selects this candidate. It does not select arbitrary manual work. For controls-OFF manual review use the existing explicit independent-session entry to the reviewer/adapter when available. No new launcher flag, discovery override, permission expansion or standalone fallback is created. If neither route can satisfy exact selection/authority, report the concrete capability blocker.

Inside the separate reviewer session the adapter verifies current context, acquires/reuses one native review run, invokes the existing semantic body once, validates/checkpoints its actual report, finalizes one disposition and verifies release. The caller owns none of these mutations. The body never starts another reviewer; an already dispatched invocation is never routed back to the selecting caller.

## Collection and resume

Use existing start/read/wait session tools and the known child identity. After return verify the existing report_reference/path/SHA-256, reviewed_candidate, reviewer_mandate, findings and disposition/incomplete against actual Git bytes, approved meaning, current native operation and handoff. A successful completed review requires accepted current native terminal and absent owner/claim, not only prose/exit/report presence. Historical approved spec, original reviewed proposal and later report checkpoint remain distinct.

Return concise six-question conclusions, blocking versus voluntary findings, attributable disposition, actual checkpoint/handoff/release and next separately authorized action. Approve does not implement; planning-return does not repair; specification-escalation does not answer or approve a changed specification. Preserve FARM-27/28 downstream evidence semantics.

For interrupted caller or uncertain dispatch/result, inspect known session, operation receipt and current Feature before effects. A matching live reviewer is collected, not restarted; a valid saved completed result is presented without replay. Missing required context or ambiguous process status is incomplete/manual inspection, never absence or permission to launch again. Respect known revocation/hold without terminating someone else's process or clearing ownership. Report exact action, target, reason, known effects and denied/pending/uncertain status. Do not switch executors/checkouts or retry after denial as a workaround.
