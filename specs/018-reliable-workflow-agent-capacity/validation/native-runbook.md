## Capability Gate

Before spawning test children, establish a supported native link between the exact collaboration child identity, its app chat ID, and the owning parent chat. The current collaboration inventory exposes canonical task names and completion status; the app archive tool requires a native chat ID. Neither activity-title matching nor a guessed ID establishes ownership.

Use a supported close/retire tool when exposed. Otherwise validate reversible app archival on a proven terminal test child: preserve its compact usable output, freshly re-observe completion and parent identity, archive the exact child, then prove a subsequent fresh launch of the same declared role. Archive acceptance alone is insufficient. Never archive unrelated or protected children, inspect private app databases, infer IDs from local session files, or substitute interrupt.

If native identity/release capabilities remain unavailable, record the specific blocker and stop. A one-time new project setup is useful only if its runtime supplies those capabilities; do not assume setup changes tool exposure. At most one initial Codex project setup may require the operator. Do not request manual scenario execution.

## Native Sequence

Read each installed definition and use its exact declared role assignments; launch fresh work children per step/pass and never reuse readiness probes. Where supported, create verified driver-owned protected occupancy children to constrain measured available slots in the same persistent chat. Keep them protected while their fixture interaction remains pending. Run at least three workflow invocations and more than twelve terminal children with at least two necessary release cycles. Demonstrate preserved independent artifacts, prompt release before the next executable node, prior-invocation entry cleanup, and fresh exact-role launches after release. Record measured availability separately from the configured candidate and any unknown effective value.

For answer-relay testing, use a real native child with an explicitly synthetic pending question. Preserve that child during cleanup, deliver the predetermined fixture response to the same child, verify continuation completes, then retain its output before release. This is a test-actor response, never a genuine human product decision. Unexpected genuine questions or consequential gates retain their explicit decision boundary.

After completing protected occupancy interactions and safely releasing those fixtures, repeat the sequence with unconstrained available slots in the same candidate-four project. Candidate four becomes a recommendation only after attributable native results pass.
