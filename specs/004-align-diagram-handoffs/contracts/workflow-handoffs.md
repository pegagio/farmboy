# Operator contract: standalone and externally selected execution

This is a human-readable semantic contract for the three existing skills. It is not a transport, API, fixed packet or new bridge command. Each skill must contain enough entry/result guidance to remain standalone portable; this document does not become a runtime loader dependency.

## Entry and examples

Standalone invokes existing named/eligible local selection and verified-ledger prerequisites where currently prescribed. External entry explicitly says the caller already selected the work. The same segment skill is invoked; no fourth selector runs. Requests can use ordinary language with relevant references instead of mandatory fields.

| Segment | Example external request | Required applicable preconditions | Saved endpoint |
|---|---|---|---|
| Prepare specification | “Use farmboy-prepare-specification for externally selected feature004 in its associated workspace. Prepare a draft from this selected intent and existing Git constitution/direction/feature references; stop before answers/review.” | Unambiguous caller-selected identity/intent/segment, accessible relevant context, associated directory; no spec approval required to draft | Usable draft/checklist plus actual document-fit findings in existing notes; Needs clarification or Awaiting spec review; ordinary clarify later |
| Prepare implementation plan | “Use farmboy-prepare-implementation-plan for externally selected004, this approved spec and supplied relevant Git references. Prepare plan/tasks/reconciliation; stop for full-plan review.” | Same contained selected artifacts/association; explicit applicable full-spec approval; existing plan/tasks/analyze capability | Complete coherent proposal with fresh read-only zero-defect analysis and Awaiting full-plan review, or exact INCOMPLETE input handoff under applicable bounded Goal rules |
| Deliver approved plan | “Use farmboy-deliver-approved-plan for externally selected004 and these approved spec/full-plan artifacts. Deliver the verified local candidate; return actual evidence for result review without integration.” | Same identity/association, applicable spec AND full-plan approval, actual implementation/convergence/check capabilities | Scoped committed local candidate plus actual evidence and Awaiting result review, or truthful incomplete outcome; no queue-status/ownership/acceptance/integration write |

Use request intent and Git project documents, not a second queue, to check fit. Supply enough version/current-state identification to resolve material ambiguity; do not require an approval register, fixed provenance packet or reapproval of unchanged work. Explicit reference access is still bounded by operator authority.

## Failure and resume examples

A missing required direction reference yields “INCOMPLETE: the selected request depends on project scope I cannot resolve from accessible references; supply the applicable direction file or resolve this specific conflict before dependent work.” It does not authorize an external fetch, invented answer or fresh selection. A mismatched pointer yields the two observed identities and a request for the caller to supply the correct associated workspace; Farmboy does not overwrite it. An unsupported integration segment yields the unsupported-segment boundary; no substitute workflow starts.

A pending handoff is returned without replay. Changed genuine answers are preserved and affected checks refreshed. Materially stale/conflicting/missing context stops only dependent work and asks for specific resolution. A routine unchanged approval is retained; meaning changes return to affected review. Unknown helper/native failure is a technical limitation, not a successful human-input endpoint. Existing native Goal completion rules still apply only to explicitly selected matching objectives, never automatic create/restart or host-state edits.

## Common result examples

A specification result says which selected request was drafted, links actual spec/checklist and relevant context/evidence, identifies base revision plus current uncommitted state when necessary, lists unresolved topics and next ordinary clarification/review. It does not require a roadmap brief for a retired queue or create a replacement fit report.

A planning result links complete spec/plan/research/data-model/contracts/quickstart/tasks and latest actual analysis, reports remaining issues or none, and identifies Awaiting full-plan review without approving it. A delivery result returns the actual successful local candidate commit and coherent artifacts/checks/convergence/documentation evidence for human UAT/final-result review; if commit fails it reports that ordinary failure, not successful delivery. Evidence/checkpoint references must describe work that exists, never future observation.

## Ownership, integration and history

One active owner per feature is enforced by the coordinator, not Farmboy. A durable draft handoff supplies data for prescribed release; ordinary clarification separately acquires authority and retains it while active. Handoff return alone performs neither acquisition nor release/transfer. Sequential owners require coordinator authority; independent features use isolation.

Historical approval of a reviewed checkpoint is distinct from latest accepted handoff. Routine flow-back preserves it; material changes need affected review. Git remains canonical for specs/plans/tasks/code/evidence. Human final-result/UAT review must explicitly authorize separate integration under project branch/target/check policy. Missing/conflicting policy is surfaced; Diagram owns serialization and database-only integration receipts referencing Git checkpoints. No implicit push, receipt-only commit, executor implementation/placement, adapter/transport, scheduler or autonomous worker follows. Integration merge alone freezes historical feature meaning; later behavior flows into new linked feature artifacts.

## Standalone preservation

All three skills keep existing local selection/context, approvals, helpers/hooks and successful local endpoints when no external request was selected. Local roadmap brief/debrief/status and configured wiki closeout stay on the local path. External entry uses supplied references and returns execution data without requiring/recreating a retired queue or absent wiki. It may still use relevant configured wiki capabilities within access authority. Both modes retain required genuine input/review stops and scope-safe native handoffs.

**Helper no-write clarification**: For helper-dependent external execution, the standard caller-established pointer must already exist and the helper's would-be persisted value must equal its existing literal value. Resolved path equality alone is insufficient: equivalent aliases/trailing separators can rewrite pointer bytes. Inspect the installed persistence convention before helpers; when it would write, ask for that specific conventional caller preparation, without silently changing environment/pointer or patching core tools. This is a precision correction within the approved no-retargeting/no-activation contract, not a new runtime mechanism.
